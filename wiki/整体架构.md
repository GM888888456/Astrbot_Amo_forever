# 整体架构

## 一句话

**终端（Amo）是唯一的脑子**：它决定回不回、怎么回、要不要叫人干活；
其余五个插件是手、眼睛和账本，等它来调。

## 一张图

```
                    你 / 群友
                        │ 消息
                        ▼
              ┌───────────────────┐
              │   终端（Amo）      │  人格 · 心流判定 · 日程 · 关系
              └───────────────────┘
                        │
        判定「这条该不该回」
          ├─ 不该回 → 丢掉（但消息仍在上下文里）
          └─ 该回  → 交给 AstrBot 的模型生成
                        │
    ┌──────────┬────────┴────────┬──────────┬──────────┐
    ▼          ▼                 ▼          ▼          ▼
  记忆        语音              相片       金融       医疗
 (写/读)   (要不要出声)      (要画什么)   (钱/工资)  (生病/治病)
```

## 一次群聊消息的完整流程

1. AstrBot 收到消息 → 终端的 handler；
2. 分流：私聊 / 群聊；
3. **群聊**：
   - 过滤：自己发的、空消息、@ 了别人、@ 了自己 —— 都不进判定
     （@ 自己 / 叫名字直接进生成；@ 别人不插话，但会记进上下文）；
   - 心流判定（小模型）：评分 → 动态阈值；
   - 通过：把这条标成「被点名」，让 AstrBot 走正常生成；
     不通过：什么都不做；
4. **私聊**：不走心流，走概率门控（＋打扰判定 ＋连续消息防抖）；
5. 生成阶段：AstrBot 调模型；终端把人格、当前状态、记忆、日程注入进去；
6. 后处理：语音插件决定这一轮要不要出声；终端写记忆、更新画像、记 token。

## 判定到底有几种

| 场景 | 走不走判定 | 用什么 |
|---|---|---|
| 群聊普通消息 | 走 | 心流小模型评分（或沉浸模式） |
| 群聊 @她 / 叫名字 | 不走 | 直接回 |
| 群聊 @别人 | 不走 | 不插话 |
| 私聊 | 不走心流 | 概率门控（看心情、关系、最近聊得多不多） |
| 挂载插件内部调用 | 不判定 | 终端直接调，或插件自己按关键词触发 |

**关于「异步」**：判定是 `async` 的，但在消息处理链里 `await` 它——
对**这一条消息**是串行的（回复要等判定），对其他会话不阻塞（事件循环照常跑）。
一次判定 = 一次小模型调用，平均 600+ 次/天；这也是为什么判定失败必须熔断，
不然上游一抖，每条消息都要多等一轮超时。

## 各插件在干什么

### 终端（Amo）—— 决策与编排

- 收消息、判要不要回、用什么语气回、要不要插话；
- 维护人格、心情、日程、关系、生理期、世界观；
- 需要人手时去调：记忆、语音、相片、金融、医疗；
- **不亲自做**：不记账、不合成语音、不画图、不诊断。

### 记忆（Astr_Amo_data）—— 只存

- 终端说「记一下」，它写进 SQLite；终端说「她记得什么」，它按关键词/时间召回；
- 生命周期：事件 7 天降权 / 15 天归档 / 30 天删除；关系、资产、偏好永久保留；
- 没有判定、没有模型调用——它是库，不是脑子。

### 语音（Astrbot_Amo_Speechsound）—— 出声

- 挂在 AstrBot 的 `on_decorating_result` 上：这一轮文字已经生成，由它决定念不念；
- 念：调 TTS → 发语音，同时把文字撤掉（避免说两遍）；
- 不念：原样发文字；出不了声且有兜底就补一条文字。

### 相片（Astrbot_Amo_Image）—— 出图

- 两条入口：终端主动分享（`draw_for`）、群里有人说「画个…/拍张照」（关键词）；
- 出图前拼一致性提示词：同一张脸、同一个环境、姿势合理；
- 自己记每日额度、冷却、人脸锚点；不碰账本。

### 金融（Astrbot_Amo_Finance）—— 账本唯一真相

- 只回答三件事：钱够不够、扣完剩多少、这个月花了多少；
- 发薪日自动入账（薪资：手动 > 人格 > 城市平均）；每月 1 号扣固定支出；
- 还做模拟炒股：持仓、行情、盈亏都在它这儿，买卖走同一个账本；
- 不判断「该不该花」，也不发消息——盈亏只把信号交给终端，由终端影响心情。

### 医疗（Astrbot_Amo_Medical）—— 生病与治疗

- 每天按概率生病（天气、经期、疲惫会加概率）；
- 自己决定去不去：小病＋余额紧就先扛，拖重了才去（`tough_it_out`）；
- 去治：先向终端报价、由终端扣款，扣到才治，扣不到继续病；
- 面板按钮 = 手动催她，绕开「自动就医」开关。

## Amo 在其中扮演什么角色

| 角色 | 具体做什么 | 不做什么 |
|---|---|---|
| 决策者 | 心流判定「这条要不要回」 | 不替模型写回复 |
| 编排者 | 决定这一轮叫语音、相片、记忆 | 不自己合成、不自己画 |
| 审批者 | 花钱走它：金额、幂等号、失败记录 | 不写余额、不算流水 |
| 记录者 | 把「发生了什么」交给记忆 | 不存记忆本体 |

一句话：**Amo 有判断力，没有手艺**。判断归它，手艺归插件，账本归金融。

## 为什么这么分

- 挂载插件挂了，聊天还能继续（语音坏了只是没声音，出图坏了只是没图）；
- 每个插件自带连接状态和面板，出问题能定位到具体是哪一块；
- 升级一个插件不用动其他插件。
